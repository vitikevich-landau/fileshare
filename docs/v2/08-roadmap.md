# 08. Роадмап v2

Нумерация продолжает v1 (M0–M6 завершены). Каждый этап — вертикальный срез:
заканчивается работающей системой, а не «слоем без потребителя». Порядок выбран
так, чтобы TUI появился как можно раньше (это самая видимая часть), но не раньше,
чем ему будет с чем разговаривать.

## M7 — Протокол v2 + VFS (фундамент)

- `protocol_v2.{hpp,cpp}`: HELLO/AUTH_*, LIST_DIR/STAT/CHECKSUM, DOWNLOAD_* c
  transfer_id, ERROR-коды v2. Юнит-тесты round-trip + malformed (образец —
  `test_protocol.cpp`).
- `Vfs`: листинг дерева, resolve с защитой от traversal, ленивый checksum-кэш
  с персистентностью. Тесты: пути с `..`, симлинки наружу, кириллица/пробелы
  в именах, пустые и глубокие деревья.
- `Session` + `MessageDispatcher` с таблицей «сообщение → мин. роль»
  (auth пока заглушка `auth_mode=none`).
- Сервер собирается как демон (`--config`, без stdin), Docker обновлён.
- **Готово, когда**: тестовый клиент (простой скриптовый, не TUI) обходит дерево
  и скачивает файл с докачкой через протокол v2; e2e-тест в ctest.

## M8 — Аутентификация и сессии

- users.json, Argon2id (libsodium; флаг `FILESHARE_USE_SODIUM`), challenge–response,
  бан за перебор, handshake-таймаут, `max_sessions_per_user`.
- `--add-user`, `--reset-password`, `--check-config`.
- Тесты: успех/неудача, replay перехваченного proof, параллельные логины,
  таймаут полуоткрытого соединения.
- **Готово, когда**: неаутентифицированное соединение не может получить листинг;
  замер: время входа < 500 мс (Argon2-параметры сбалансированы).

## M9 — TUI-клиент: минимальный командер

- FTXUI + каркас: ConnectScreen → CommanderScreen; профили подключений
  (пока без сохранения пароля).
- Две панели (локальная + удалённая), навигация, Tab, сортировка, F10.
- F5-скачивание с прогрессом, докачка, очередь передач; ошибки — красным в лог
  операций; `--batch`-режим.
- `AppState` отделён от FTXUI, покрыт юнит-тестами.
- **Готово, когда**: с Windows- и Linux-клиента можно зайти на Docker-сервер,
  походить по дереву и скачать файл, не притрагиваясь к мышке и не читая доку
  (руки из MC работают).

## M10 — Живость: события, подсветка, устойчивость

- inotify → EventBus → `SUBSCRIBE`/`EVENT_FS`; дебаунс.
- Подсветка нового (last_seen + live-события), `Ctrl+N`, индикатор соединения,
  авто-реконнект с повторной аутентификацией и перечиткой панелей.
- PING-хартбит, idle-таймаут на сервере.
- Fault-injection-тесты: обрыв во время листинга/закачки/события, реконнект.
- **Готово, когда**: файл, подброшенный в share на сервере, в течение секунды
  появляется в открытой панели клиента подсвеченным; выдёргивание кабеля
  (kill -9 сервера) приводит к плашке и авто-восстановлению после рестарта.

## M11 — Админ: живое управление сервером

- SettingsHub (снапшоты), RateLimiter (per-client + global, событийный
  backpressure), hot-параметры из [03-server-daemon.md](03-server-daemon.md).
- ADMIN_*-протокол + AdminService (белый список ключей, валидация, аудит).
- Админ-панель в TUI: Обзор / Клиенты (kick) / Настройки (живое редактирование) /
  Журнал; graceful shutdown из UI.
- SIGHUP + inotify на config.json.
- Тесты: смена лимита во время активной закачки реально меняет скорость
  (замер в интеграционном тесте), конкурентные apply, невалидные значения.
- **Готово, когда**: админ с клиента снижает лимит с 50 до 5 MB/s и видит, как
  проседает скорость у активной закачки — без разрыва и рестарта.

## M12 — Пользователи как система (перспектива)

- SQLite вместо users.json; ADMIN_USER_* (list/add/disable/quota/role);
  вкладка «Пользователи» в админ-панели.
- Виртуальные корни: public + home per user; изоляция в VFS; фильтрация EVENT_FS
  по видимости.
- **Готово, когда**: два пользователя не видят home друг друга ни листингом,
  ни прямым путём, ни через события.

## M13 — Upload и квоты (перспектива)

- UPLOAD_*-протокол, `.upart` + переименование, докачка залива.
- Квоты: проверка до передачи, инкрементальный used_bytes + self-healing пересчёт,
  полоска квоты в TUI; F5/F6/F7/F8 в сторону сервера в пределах прав.
- **Готово, когда**: залив файла сверх квоты отклоняется мгновенно; параллельные
  заливы не ломают учёт (тест на гонки).

## M14 — TLS (перспектива)

- `TlsConnection` (OpenSSL) в epoll-машину состояний; TOFU-pinning fingerprint'а
  в профиле клиента; красное предупреждение при смене сертификата.
- **Готово, когда**: tcpdump на сервере не показывает содержимого файлов и логинов.

## Порядок и зависимости

```
M7 ──► M8 ──► M9 ──► M10 ──► M11 ──► M12 ──► M13 ──► M14
фунд.   auth   TUI    live    admin   users   upload  TLS
└───────────── v2.0 (публикуемый результат) ─────────┘
              M7–M11 = «то, что описано в идее»
              M12+   = перспектива
```

## Сквозные правила (наследуются из v1)

- Ноль варнингов `-Wall -Wextra -Wpedantic -Wconversion -Wshadow` / `/W4`.
- Каждый этап проходит ASan; конкурентные части — TSan.
- Битый ввод рвёт ровно одно соединение — правило распространяется на все новые
  сообщения; на каждый новый парсер — malformed-тесты.
- Загрузочный тест `fileshare_loadtest` обновляется на v2 в M8 (auth) и гоняется
  после M11 (rate limiter не должен стоить заметного CPU при выключенных лимитах).
